How to match? (2/3): Greedy matching
• Greedy (nearest neighbor) matching: One at a time
- Not as good, but computationally fast (for large dataset)
- Steps)
1. Randomly order list of treated units and control units
2. Start with the first treated unit. Match to the control with the smallest distance.
3. Remove the matched control from the list of available matches
4. Move on to the next treated unit. Match to the control with the smallest distance
5. Repeat steps 3 and 4 until you have matched all treated units.
- R packages; MatchIt (No good Python packages yet: You can use ryp2 package to run R in Python)
(For K:1 matching – many-to-one, after everyone has 1 match, go through the list again and find 2nd matches.
Repeat until k matches
• Caliper: We might prefer to exclude treated units for whom there does not exist a good match
- A bad match can be defined using a caliper – maximum acceptable distance.
- Only match a treat unit if the best match has distance less than the caliper.

How to match? (3/3): Optimal matching
• Optimal matching: in terms of global distance
- Better, but computationally demanding: 100 treated units and 1000 controls results in 100,000 possible pairings
(1 million treatment-control pairing is feasible, 1 billion parings is likely not feasible.)
- Minimizes global distance measure (e.g., total distance)
- Consider all possible matches between treatment and control
- Can be solved with network flow optimization problem
- R packages: optmatch, rcbalance

Analysis after matching (1/2): Permutation test (randomization test)
• Permutation tests
- Compute test statistic from observed data (after matching)
- Assume null hypothesis of no treatment effect is true
- Randomly permute treatment assignment within pairs and re-compute test statistic
- Repeat many times and see how unusual observed statistic is

Heterogeneous Treatment Effects (HTE): CATE Estimation (1/4)
The Causal Forest Solution (GRF with IV)
To measure Heterogeneous Treatment Effects—how a treatment affects different people differently—
we have to move beyond finding a single "average" number.
If we are testing a new blood pressure medication, DML gives us the Average Treatment Effect (ATE): "On
average, this pill lowers blood pressure by 5 points."
But a doctor doesn't care about the average. They want the Conditional Average Treatment Effect
(CATE): "How much will this pill lower blood pressure for a 65-year-old woman with a history of smoking?"
To answer that while still using an Instrumental Variable (IV) to handle hidden confounders, we need a
specialized algorithm called a Causal Forest (often implemented as a Generalized Random Forest, or
GRF).

Heterogeneous Treatment Effects (HTE): CATE Estimation (2/4)
Why Standard Random Forests Fail
A standard Random Forest is built for prediction. It looks at the data and asks, "What splits will help me
predict the outcome most accurately?" It might split the data by Age > 50, then by Smoker = Yes, trying to
group people with similar blood pressure together.
But we aren't trying to predict blood pressure. We are trying to measure a causal effect (the difference the
pill makes). You cannot calculate an effect for a single person because you only observe them either taking
the pill or not taking it—you never see both.
If you use a standard Random Forest, it will split the data based on who is naturally healthy versus
unhealthy, completely ignoring the causal effect of the pill.

Heterogeneous Treatment Effects (HTE): CATE Estimation (3/4)
The Causal Forest Solution (GRF with IV)
A Causal Forest fundamentally changes the rules of how the trees are built. It stops optimizing for prediction and
starts optimizing for causal variance.
1. The Setup (Residualization)
Just like in standard DML-IV, we first use machine learning to "scrub" the background noise. We predict the Outcome,
the Treatment, and the Instrument using all known covariates, and we save the residuals (the "surprises").
2. The "Honest" Splitting Rule
Now we build the Causal Forest using those residuals. Instead of splitting the data to minimize prediction error, the
Causal Forest splits the data to maximize the difference in the treatment effect between the two new branches.
It uses the Instrumental Variable math inside every single split.
The split question is no longer: "Does splitting by Age > 50 help me predict blood pressure?“
The split question is now: "If I use my Instrument to calculate the 2SLS causal effect, is the effect significantly different
for people over 50 versus people under 50?"

Heterogeneous Treatment Effects (HTE): CATE Estimation (4/4)
The Causal Forest Solution (GRF with IV)
A Causal Forest fundamentally changes the rules of how the trees are built. It stops optimizing for prediction and
starts optimizing for causal variance.
3. Cross-Fitting (Honesty)
To prevent the model from hallucinating effects, Causal Forests use a technique called "honesty" (which is similar to
cross-fitting in DML).
It uses one half of the data to decide where to make the splits (e.g., deciding that Age > 50 is a good split).
It uses the other half of the data to actually calculate the causal effect within those newly created leaves.
The Final Result: Personalized Estimates
Once the forest is built (using hundreds of these specialized trees), you can drop a new patient into the model.
